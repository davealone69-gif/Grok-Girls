# Building the Grok Girls Android APK

## One-time setup
The toolchain lives in `/home/user/.toolchain/` (gitignored):
- `jdk21` — JDK 21.0.5+11. **Required**: Capacitor 8 cannot build on JDK 17.
- `sdk` — platform-tools r37.0.1, android-35, build-tools 35.0.0 + 34.0.0
- `node22` — v22.20.0, required by the Capacitor CLI

Also required:
- `android/local.properties` containing `sdk.dir=/home/user/.toolchain/sdk` (gitignored)
- **4 GB of swap.** The 2-CPU / 1.9 GB builder OOMs without it
  (`Gradle build daemon disappeared unexpectedly`):
  ```
  sudo fallocate -l 4G /swapfile && sudo chmod 600 /swapfile
  sudo mkswap /swapfile && sudo swapon /swapfile
  ```
- No dev/preview servers running — they compete for RAM.

## Build
```bash
export JAVA_HOME=/home/user/.toolchain/jdk21
export ANDROID_HOME=/home/user/.toolchain/sdk
export ANDROID_SDK_ROOT=/home/user/.toolchain/sdk
export PATH=/home/user/.toolchain/node22/bin:$JAVA_HOME/bin:$PATH

npm run build && npx cap sync android
cd android && ./gradlew assembleDebug assembleRelease \
  --no-daemon --console=plain --max-workers=1
```
Takes ~1-2 min. Outputs:
- `android/app/build/outputs/apk/debug/app-debug.apk` (debug-signed, installable)
- `android/app/build/outputs/apk/release/app-release-unsigned.apk`

## Verification (do not trust the build log alone)
```bash
export PATH=/home/user/.toolchain/sdk/build-tools/35.0.0:$PATH

apksigner verify --print-certs app-debug.apk        # Signer #1 CN=Android Debug
aapt2 dump badging app-debug.apk | grep ^package    # ai.grokgirls.studio
aapt2 dump xmltree --file AndroidManifest.xml app-debug.apk \
  | grep -E 'RUN_COMMAND|com.termux|cleartext'

# Ollama plugin is compiled into the dex
unzip -p app-debug.apk classes5.dex | strings | grep -i ollama

# Shipped web bundle has no Hermes
unzip -qo app-debug.apk "assets/public/*" -d /tmp/apkchk
grep -rli hermes /tmp/apkchk/assets/public/   # must return nothing
```

## Gotchas
- `android/app/capacitor.build.gradle` pins `VERSION_21` and is **regenerated by
  `cap sync`** — never hand-edit it. Set targets in `android/app/build.gradle`.
- `./gradlew` ships without the exec bit after a fresh clone: `chmod +x gradlew`.
- Gradle's `~/.gradle/caches` will blow the inotify limit and crash vite; that's
  why `vite.config.ts` ignores `**/.gradle/**` and `**/artifacts/**`.
- Package id is `ai.grokgirls.studio`. The `native/` Compose project is a
  separate app (`com.aura.avatarstudio`) that also compiles during this build.

## The two local servers

The app talks to two independent phone-local servers. They have separate
ports, separate Termux commands, and separate lifecycles — neither can start
or stop the other.

```
Android App -> Local Server Manager (SdLocalPlugin)   -> Termux -> sd-server :1234
Android App -> Local LLM Client     (OllamaLocalPlugin) -> Termux -> ollama   :11434
```

| | Images | Text |
|---|---|---|
| Server | sd-server | Ollama |
| Port | 1234 | 11434 |
| API | `POST /sdapi/v1/txt2img` | `POST /v1/chat/completions` |
| Plugin | `SdLocal` | `OllamaLocal` |
| Service | `src/services/sdLocal.ts` | `src/services/ollama.ts` |
| Suite | `tests/sd_suite.py` (57) | `tests/ollama_suite.py` (18) |

Both go through a native Kotlin bridge rather than WebView `fetch`, for the
same two reasons: neither server sends CORS headers, and `http://127.0.0.1`
is blocked as mixed content from the `https://localhost` WebView origin.
`network_security_config.xml` whitelists loopback cleartext (it is
port-agnostic, so one `127.0.0.1` entry covers both).

### sd-server setup in Termux
Install a build that exposes the A1111 API, then either put it on PATH as
`sd-server` or create `~/sd-server.sh` to launch your build. The app runs it
with `--port 1234` on loopback and polls `127.0.0.1:1234/` until it answers.
Start failures are logged to `~/sd-server.log`.
